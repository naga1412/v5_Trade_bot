# PR10.7 — hotfix: SPOT price-fetch resilience + UI null-safe rendering

**Status:** spec drafted 2026-05-20 (same morning, after PR10.6 operator visual check failed). 3 fixes in one PR per operator's approved scope.

**Branch:** `feat/pr10.7-hotfix-spot-price-resilience` (off `origin/dev`).

**Trigger:** PR10.7 diagnostic (run 26147552565) revealed that the deployed `fetch_spot_prices` is failing with **HTTP 400** on every cold-load because the symbol batch contains duplicates (AVAXUSDT×2, BTCUSDT×2, SOLUSDT×2, LUNCUSDT×2, FIDAUSDT×2) AND symbols not valid on Binance SPOT (EDENUSDT futures-only, LUNCUSDT delisted, PAXGUSDT/XAUTUSDT restricted, UUSDT suspect). Binance SPOT rejects the entire batch if ANY symbol is invalid → `prices={}` returned → every Open Position row gets `current_price=None`/`unrealized_pnl=None`. The PR10.6 WS-tick path is working but only incrementally updates rows; cold-load failure leaves Now/P&L empty across the dashboard.

**Operator-approved scope:** FIX 1 (ticker robustness) + FIX 2 (universe blacklist) + FIX 3 (frontend null tooltip). PR10.8 (healer expansion) is queued separately.

---

## 1. FIX 1 — `fetch_spot_prices` robustness

**File:** `backend/app/data/binance_ticker.py`

**Changes:**
1. **Dedupe** input symbols list via `sorted(set(symbols))` before building the batch.
2. **Per-symbol fallback** on batch HTTP 400 (or any HTTPError): iterate over symbols, hit `/api/v3/ticker/price?symbol=X` individually. Skip on per-symbol failure (log WARNING with symbol + reason).
3. **Partial-dict return** (not empty): if 18 of 20 succeed individually, return those 18; row-render with the 2 failing symbols falls back to `current_price=None` per existing route logic.
4. **Metrics counters** (module-level `dict` for in-process counting; surfaced via `/metrics` endpoint if it exists, or just inspected via grep in dev):
   - `spot_price_fetch_batch_rejected_total: int`
   - `spot_price_fetch_per_symbol_fallback_total: int`
   - `spot_price_fetch_per_symbol_failed: dict[str, int]` (per-symbol failure count)

**Behavior contract:**
- Empty input → `{}` unchanged.
- Single batch call when batch succeeds (no behavior regression).
- Batch HTTP error → per-symbol fallback (logged as WARNING with batch-size + reason).
- Per-symbol HTTPError → skip + WARNING `"fetch_spot_prices fallback: skip <SYM>: <reason>"` + metric increment.
- All-failure case still returns `{}` (no harder failure).
- Counters reset on process restart (in-memory only). No persistence.

**Tests** (`backend/tests/unit/test_binance_ticker_resilience.py`):
- `test_dedupe_symbols`: input `["AAA","BBB","AAA"]` → URL params include each symbol exactly once (sorted).
- `test_batch_success_returns_full_dict`: mock 200 with 3 entries → all 3 in returned dict.
- `test_batch_400_falls_back_per_symbol`: mock first `/ticker/price?symbols=[...]` → 400; per-symbol calls succeed for 2 of 3, 400 for 1 → returned dict has the 2; counter incremented; WARNING logged.
- `test_per_symbol_all_fail_returns_empty`: per-symbol calls all 400 → `{}` returned.
- `test_per_symbol_network_error_returns_partial`: 1 per-symbol call raises `httpx.ConnectError`; others succeed → partial dict + WARNING.

## 2. FIX 2 — `SHADOW_SPOT_BLACKLIST` setting + universe filter

**File:** `backend/app/config.py` + `backend/app/shadow/universe.py`

**Changes:**
1. New Setting:
   ```python
   # --- PR10.7: SPOT-invalid symbols ----------------------------------
   # Symbols that exist on Binance Futures (or are delisted) but fail
   # /api/v3/ticker/price. Without blacklisting, fetch_spot_prices
   # falls back to per-symbol calls (slow but partial-resilient via
   # FIX 1). Blacklisting upstream is cleaner.
   #
   # UUSDT specifically — Binance Futures has "U" perpetual; SPOT only
   # has UNIUSDT (Uniswap). Including UUSDT in our universe must be
   # legacy data from when the universe came from fapi. Filter it.
   SHADOW_SPOT_BLACKLIST: list[str] = [
       "EDENUSDT", "LUNCUSDT", "PAXGUSDT", "XAUTUSDT", "UUSDT",
   ]
   ```
2. `fetch_top_n_usdt_spot` in `universe.py` — apply blacklist filter after fetching from `/api/v3/ticker/24hr`. The Binance SPOT 24h endpoint may include symbols whose `/ticker/price` rejects them (region restrictions, status anomalies). Defense in depth.
3. **`fetch_spot_prices` ALSO applies blacklist** as an early filter — drops blacklisted symbols silently before the batch even happens. (Belt-and-suspenders since the universe filter may not refresh immediately.)

**Tests** (`backend/tests/unit/test_universe_spot_blacklist.py` + extend `test_binance_ticker_resilience.py`):
- `test_universe_filters_blacklist`: SPOT 24h response contains EDENUSDT → universe entries exclude it.
- `test_fetch_spot_prices_filters_blacklist`: input `["BTCUSDT","EDENUSDT"]` → request URL only contains BTCUSDT.

## 5. V-7 latency budget

- Happy-path (batch succeeds): one HTTP call. Unchanged.
- Worst case (batch 400 + 20 symbols): 1 batch attempt + 20 per-symbol calls = 21 HTTP calls. Each ~30ms = ~630ms added latency to cold-load. Acceptable (this is on a manual page-refresh, not the dispatcher hot path).
- Operator long-term fix: trim universe to truly-valid-on-SPOT symbols so batch always succeeds.
