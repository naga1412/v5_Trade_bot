**Status:** spec drafted 2026-05-20; autonomous-approved against operator's overnight criteria (scope strictly 4 T-UI tasks, no new operator-config flags for behavior-restoring fixes, V-7 ≤ 5ms, no dispatcher trading logic changes, no audit-chain whitelist changes).

**Strategic context:** Operator observed Open Positions card "Now / P&L" columns stay static for hours; per-asset stats card frozen between manual refreshes; no idea when data was last computed. ## 1. Diagnostic findings (2026-05-19 → 2026-05-20)

### T-UI.1 root cause — pnl_tick WS stream silent

Probe `ui-data-pipeline-check` against prod showed:
- **U-1** (mark_price / live_price / pnl_calc log activity, last 30 min): **empty**.
- **U-2** (open_position / position update log activity, last 30 min): **empty**.

Code analysis confirmed:
- `backend/app/ws/shadow_updates.py:115` defines `publish_pnl_tick(...)`.
- `grep -rn publish_pnl_tick backend/app/` finds **zero callers**. The function is dead code.
- `publish_position_opened` / `publish_position_closed` ARE called from `backend/app/shadow/worker.py:642` / `:432` — those events fire on actual open/close transitions only.
- Frontend `useShadowUpdates.ts` subscribes to all three event types; `useOpenPositionsLive.ts:42-68` correctly merges `lastPnlTick` into the rendered position rows.

Net effect: between candle-close transitions (1h cadence per TF; sometimes hours between open/close events for a given symbol), the Open Positions card "Now/P&L" columns receive zero updates. On page-refresh the `/api/v1/bot-status/open-positions` endpoint cold-loads a Binance SPOT batch price ticker (lines 393–413 of bot_status.py) so the *first* paint is fresh, but the values then freeze until the user reloads or a position open/close happens.

### T-UI.2 root cause — per-asset stats no polling

- `backend/app/api/routes/bot_status.py:535` `/per-asset` recomputes stats live from `shadow_trades` on every GET (no caching).
- `frontend/src/tabs/BotStatus/hooks/usePerAssetStats.ts:22-39` only refetches on mount + `days`-state-change + manual `refetch()`. **No time-based polling. No WS trigger.**
- Stats appear "frozen" because nothing prompts a re-fetch when new shadow_trades close.

### T-UI.3 gap — no timestamp on stats responses

- `OpenPositionOut` schema (line 246, `app/api/schemas.py`) has `opened_at` but no `as_of` / `computed_at`.
- `PerAssetStatOut` schema (line 267) has no `last_trade_closed_at` or `computed_at` field at all.
- UI cannot label "stats as of X minutes ago" without these.

### T-UI.4 gap — no UI-freshness watcher

- Probe **U-4** (worker heartbeats matching `stats|refresh|cache|snapshot|aggregator|valid`): 5 rows. None of them owns "UI read-side freshness" — they are: `mtf_cache_ttl_refresh_task`, `intermarket_snapshot_task`, `prediction_validator_task`, `universe_refresh_task`, `mtf_cache_prewarm_task`.
- The existing `worker_watchdog` (PR #97) alerts on worker staleness but only **auto-restarts non-stateful workers** registered with `worker_supervisor`. It does NOT monitor downstream UI data-freshness (e.g. "have we published a pnl_tick in the last 90 minutes despite N open positions?").
- FU-28 is the spec name for the new "UI data freshness monitor + selective auto-recycle" worker that detects + remediates this class of read-side staleness.

## 2. Architecture overview

```
shadow_worker  ─┬─→  publish_position_opened  → WS ── frontend useShadowUpdates
                ├─→  publish_position_closed  → WS ── frontend useShadowUpdates
                └─→  publish_pnl_tick        → WS ── frontend useShadowUpdates  ← T-UI.1 wires this on every non-closing candle
                                                       │
                                                       ▼ updates current_price + unrealized_pnl_pct
                                       useOpenPositionsLive.tsx (apply tick in-place)

/api/v1/bot-status/per-asset (cold compute every GET)
        ↑
        └── usePerAssetStats hook  ← T-UI.2 adds 60s polling interval (configurable, default ON)

response payloads:
  OpenPositionOut   ← T-UI.3 adds `as_of: datetime` (server NOW())
  PerAssetStatOut   ← T-UI.3 adds `last_trade_closed_at: datetime | None` + `computed_at: datetime`

new worker:
  ui_freshness_monitor  ← T-UI.4 (FU-28) — every 5 min:
        a) read open-positions count + last_pnl_tick_emit timestamp (in-memory module-level var on shadow_updates module, exposed via getter)
        b) if open_count > 0 AND (now - last_emit) > FU28_STALE_PNL_TICK_THRESHOLD_SECONDS (default 1800 = 30 min):
              - log WARNING with details
              - record_heartbeat status="degraded"
              - if FU28_AUTO_RECYCLE_ENABLED (default False): call worker_supervisor.recycle("shadow_worker") — only if shadow_worker is registered as non-stateful, otherwise alert-only
        c) heartbeat status="ok" on healthy passes
```

## 3. Per-task deliverables

### T-UI.1 — Wire `publish_pnl_tick` from shadow worker per-candle hook

**Files:**
- Modify: `backend/app/shadow/worker.py` (insert tick publish in `_maybe_close_position` before the early-return when `decision is None`)
- Modify: `backend/app/ws/shadow_updates.py` (add module-level `_last_pnl_tick_at: dict[str, datetime]` + `get_last_pnl_tick_at(symbol)` accessor used by T-UI.4)
- Modify: `backend/app/shadow/worker.py` (import + small helper `_compute_unrealized_pnl_pct(pos, close_price)` — reuse `app.data.binance_ticker.compute_unrealized_pnl_pct` which already exists)
- Test: `backend/tests/unit/test_shadow_worker_pnl_tick.py` (new — patches `shadow_updates.publish_pnl_tick`, fires one non-closing candle, asserts the publish was awaited with correct kwargs)

**Behavior contract:**
- On every closed candle that does NOT trigger an exit, emit one `publish_pnl_tick` event per open position on that `(symbol, tf)` key.
- Catches and logs any exception inside the publish path (the WS broker may be temporarily down). DOES NOT abort candle processing.
- Updates `_last_pnl_tick_at[symbol] = candle.ts` after a successful publish (read by T-UI.4).

**Why this is the right cadence:** 1h-aligned tick is sufficient for the bot's current `mode=manual` observability use case (operator only checks the dashboard intermittently, not millisecond traders). Higher-frequency ticks (per-second) would require a fundamentally different streaming architecture (Binance SPOT ticker WS subscription per open symbol) which is out of scope. The frontend hook already handles tick-then-fetch reconciliation cleanly.

### T-UI.2 — Add time-based polling to per-asset stats hook

**Files:**
- Modify: `frontend/src/tabs/BotStatus/hooks/usePerAssetStats.ts` (add `setInterval` polling with default 60000ms; cleanup on unmount; configurable via prop)
- Test: `frontend/src/tabs/BotStatus/hooks/usePerAssetStats.test.ts` (new — mock `api.perAssetStats`, advance fake timers, assert fetch is called again after polling interval)

**Behavior contract:**
- Default `pollIntervalMs = 60_000` (60s). Reasonable for stats that only change on closed shadow trades.
- `pollIntervalMs = 0` disables polling (operator opt-out, kept for testability).
- Polling is paused while a fetch is in-flight (no overlapping requests).
- Interval is cleared on unmount and on `days` change (effect dependency).

**Why no time-based polling on Open Positions:** T-UI.1's pnl_tick WS stream covers it; adding HTTP polling on top would duplicate work. Frontend hook already refetches on `lastOpened` / `lastClosed` WS events.

### T-UI.3 — Add timestamps to stats responses

**Files:**
- Modify: `backend/app/api/schemas.py` (add `as_of: datetime` to `OpenPositionOut`; add `computed_at: datetime` + `last_trade_closed_at: datetime | None` to `PerAssetStatOut`)
- Modify: `backend/app/api/routes/bot_status.py` (populate the new fields in both endpoints)
- Modify: `frontend/src/lib/api.ts` (mirror new TS interface fields)
- Modify: `frontend/src/tabs/BotStatus/components/OpenPositionsCard.tsx` (display "as of HH:MM:SS" footer)
- Modify: `frontend/src/tabs/BotStatus/components/PerAssetStatsCard.tsx` (display "computed at HH:MM:SS · last trade: HH:MM:SS / —" footer)
- Test: `backend/tests/integration/test_open_positions_as_of.py` (new — asserts `as_of` is within 2s of test clock)
- Test: `backend/tests/integration/test_per_asset_computed_at.py` (new — asserts `computed_at` is within 2s of test clock; `last_trade_closed_at` matches latest seeded closed_at)

**Behavior contract:**
- `as_of` = server `datetime.now(UTC)` at endpoint entry.
- `computed_at` = server `datetime.now(UTC)` at endpoint entry.
- `last_trade_closed_at` = `MAX(closed_at)` across the per-symbol trade set; `None` if no closed trades in the window.
- Frontend renders timestamps in local time using `Intl.DateTimeFormat` (existing pattern in other cards).

### T-UI.4 — `ui_freshness_monitor` worker (FU-28)

**Files:**
- Create: `backend/app/workers/ui_freshness_monitor.py`
- Modify: `backend/app/ws/shadow_updates.py` (already covered by T-UI.1: module-level `_last_pnl_tick_at` + accessor)
- Modify: `backend/app/ops/worker_registry.py` (entry #20)
- Modify: `backend/app/main.py` (var init + spawn + shutdown)
- Modify: `backend/app/config.py` (3 new settings — see §5)
- Modify: `backend/tests/unit/test_worker_registry_consistency.py` (`WORKER_SOURCE_MODULES` entry)
- Test: `backend/tests/workers/test_ui_freshness_monitor.py` (new — 4 tests: healthy pass, stale → log WARNING, recycle-disabled → alert-only, recycle-enabled → calls `worker_supervisor.recycle`)

**Behavior contract:**
- Polls every `FU28_POLL_INTERVAL_SECONDS` (default 300 = 5 min).
- Reads open position count via `list_open_positions` (existing helper).
- Reads `_last_pnl_tick_at` snapshot per symbol from `shadow_updates`.
- If `open_count > 0` AND any open symbol has `(now - last_emit) > FU28_STALE_PNL_TICK_THRESHOLD_SECONDS` (default 1800 = 30 min) AND `now - max_last_emit_overall > threshold`:
  - Log WARNING: `ui_freshness_monitor: stale pnl_tick — open=N, last_tick_age=Xs, threshold=Ys`
  - Record heartbeat `status="degraded"` with details.
  - If `FU28_AUTO_RECYCLE_ENABLED=True` AND shadow_worker is registered as non-stateful with worker_supervisor: call `worker_supervisor.recycle("shadow_worker")`. Else alert-only.
- Otherwise heartbeat `status="ok"`.
- Fail-open on any internal exception: log + heartbeat `status="error"` + return; never propagate.

**Why default `FU28_AUTO_RECYCLE_ENABLED=False`:** shadow_worker is currently registered as `stateful=True` in worker_registry.py (verified by reading the file). Auto-recycling a stateful worker is unsafe without further design work. The flag exists for forward-compat if shadow_worker becomes recyclable later.

## 6. V-7 latency budget

- T-UI.1 publish_pnl_tick — async fire-and-forget WS broadcast; benchmarked equivalent path (`publish_position_closed`) is ~0.4ms per call. With ≤30 open positions per cycle, worst case ~12ms additional candle-processing time per closed-candle batch. Shadow worker's candle cadence is 1h, so this is irrelevant to the dispatcher hot path. **Δp99 dispatcher impact: 0ms** (the gate isn't on the dispatcher path at all).
- T-UI.2 frontend polling — 1 HTTP GET per 60s, payload <20KB. No backend hot-path impact.
- T-UI.3 timestamps — single `datetime.now(UTC)` per endpoint entry. Sub-microsecond. Δp99 endpoint: <0.1ms.
- T-UI.4 monitor worker — runs every 5 min in its own task. Reads `_last_pnl_tick_at` dict snapshot + one `list_open_positions` DB query. **No dispatcher hot-path impact.**

**Overall V-7 budget: well under the 5ms estimate; dispatcher hot path unchanged.**

## 7. Rollback

- T-UI.1 rollback: revert the `publish_pnl_tick` call site in `_maybe_close_position`. WS stream returns to its current silent state. Frontend correctly handles "no tick events" (existing behavior).
- T-UI.2 rollback: revert the `setInterval` block in `usePerAssetStats.ts`. Stats stop polling.
- T-UI.3 rollback: revert schema fields (backwards-compatible: frontend doesn't crash if fields are missing because of `?? null` defaults in TS interfaces).
- T-UI.4 rollback: env `FU28_AUTO_RECYCLE_ENABLED=False` disables the only impact (recycle action). The monitor itself is observation-only and safe to leave running. To fully stop: remove worker registry entry + spawn block in `main.py`.

Single revert: `git revert <PR10.5-squash-merge-sha>` reverses all four tasks.
