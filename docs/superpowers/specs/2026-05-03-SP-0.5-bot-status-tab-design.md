## 1. Purpose

Build the **infrastructure that turns the platform from "1-asset live prediction" into "30-asset autonomous shadow trading"** — without touching real money. Two outcomes:

1. **Visible product feature** — the user gets a 4-tab UI showing what the bot WOULD do across 30 assets, with running stats. Genuinely useful from day one.
2. **Foundation for autonomous trading (SP-8)** — generates the 30/100-trade history that the autonomous trading spec §4.1 requires before Telegram-approve mode unlocks.

This is the bridge sub-project: visible product value + infrastructure investment in one. Implemented during the Oracle Ampere wait so that when Oracle lands, deploy ships SP-0 + SP-0.5 together.

### Non-goals

- **No real money trading.** Period. That's SP-8.
- **No Telegram bot integration.** That's SP-8 too.
- **No multi-user isolation.** Single-user shadow trades; SP-0.7 wraps in `user_id` later.
- **No multi-timeframe.** 1h only (matches SP-0). Multi-TF is a future enhancement.
- **No tax tracking.** Shadow trades are pretend money — no tax events.
- **No leverage.** Shadow trades are 1× notional only (sizing concept doesn't apply without real margin).

### 3.2 Shadow worker lifecycle

Started by `app.main:lifespan` (alongside the existing `live_prediction` worker):

```python
# In app/main.py lifespan:
shadow_worker = start_shadow_worker()  # spawns 30 streams, runs forever
try:
    yield
finally:
    shadow_worker.cancel()
```

The shadow worker:

1. On startup: query `asset_universe` table for current top 30 (refresh via REST if stale > 24h)
2. Open one WS connection to Binance with 30 combined `@kline_1h` streams
3. For each closed candle (`k.x == True`):
   - Append to in-memory bars dict for that asset (keep last 500 bars)
   - Compute scoring (`build_prediction(symbol, "1h", bars)`)
   - If score > +0.30 (LONG threshold) AND no open position on this asset AND not in cooldown → open shadow LONG
   - If score < -0.50 (SHORT threshold) AND ditto → open shadow SHORT
4. For each closed candle on an asset with an open position:
   - Check if HIGH ≥ TP (long) or LOW ≤ SL (long); reverse for short → close
   - Increment `bars_held`; if ≥ 24 → close at this candle's close (timeout)

### 3.4 Universe refresh job

A separate Celery task (or simple `asyncio.create_task` with daily sleep):

```python
async def refresh_asset_universe():
    while True:
        # Fetch from Binance: GET /api/v3/ticker/24hr
        tickers = await binance.get_24h_tickers()
        usdt_pairs = [t for t in tickers if t["symbol"].endswith("USDT")]
        usdt_pairs.sort(key=lambda t: float(t["quoteVolume"]), reverse=True)
        top_30 = [t["symbol"] for t in usdt_pairs[:30]]

        # Persist
        await save_asset_universe(top_30)

        # If new top-30 differs from current shadow worker stream subscriptions,
        # signal worker to reconfigure (close streams for fallen-out assets,
        # open streams for new entries)
        await signal_universe_change(top_30)

        # Sleep until next 00:00 UTC
        await sleep_until_midnight_utc()
```

Falling-out assets: if any have an open shadow position, position is allowed to close naturally (SL/TP/timeout); after that, no new entries.

## 4. Database schema

### 4.1 New tables (audit-chained per §5.14)

```sql
-- Asset universe — top 30 USDT pairs, snapshot per refresh
CREATE TABLE asset_universe (
    id BIGSERIAL PRIMARY KEY,
    symbol TEXT NOT NULL,
    quote_volume_usd_24h DOUBLE PRECISION NOT NULL,
    rank INTEGER NOT NULL,                    -- 1..30 within snapshot
    snapshot_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (symbol, snapshot_at)
);
CREATE INDEX asset_universe_snapshot_idx ON asset_universe (snapshot_at DESC, rank);

-- Closed shadow trades (full history, hash-chained for audit)
CREATE TABLE shadow_trades (
    id BIGSERIAL PRIMARY KEY,
    symbol TEXT NOT NULL,
    timeframe TEXT NOT NULL DEFAULT '1h',
    direction TEXT NOT NULL CHECK (direction IN ('LONG','SHORT')),
    entry_price DOUBLE PRECISION NOT NULL,
    stop_loss DOUBLE PRECISION NOT NULL,
    take_profit DOUBLE PRECISION NOT NULL,
    position_size_usdt DOUBLE PRECISION NOT NULL,    -- always 30.0 for SP-0.5
    entry_score DOUBLE PRECISION NOT NULL,            -- aggregate score at entry
    entry_confidence DOUBLE PRECISION NOT NULL,
    layer_scores JSONB NOT NULL,                      -- L1/L3/L5 + (later) L7/L8/L10
    entry_atr DOUBLE PRECISION NOT NULL,              -- ATR used for SL/TP
    exit_price DOUBLE PRECISION,
    exit_reason TEXT CHECK (exit_reason IN ('TAKE_PROFIT','STOP_LOSS','TIMEOUT')),
    pnl_pct DOUBLE PRECISION,
    pnl_usdt DOUBLE PRECISION,
    bars_held INTEGER,
    opened_at TIMESTAMPTZ NOT NULL,
    closed_at TIMESTAMPTZ,
    inputs_hash TEXT NOT NULL,                        -- per §5.4 reproducibility
    model_version TEXT NOT NULL DEFAULT 'sp-0.5',
    signal_id TEXT NOT NULL UNIQUE,                   -- for chart deeplinks
    prev_hash TEXT NOT NULL,
    row_hash TEXT NOT NULL UNIQUE
);
CREATE INDEX shadow_trades_symbol_opened_idx ON shadow_trades (symbol, opened_at DESC);
CREATE INDEX shadow_trades_closed_idx ON shadow_trades (closed_at DESC) WHERE closed_at IS NOT NULL;
CREATE INDEX shadow_trades_signal_id_idx ON shadow_trades (signal_id);

-- Currently-open shadow positions
CREATE TABLE shadow_open_positions (
    id BIGSERIAL PRIMARY KEY,
    symbol TEXT NOT NULL UNIQUE,                      -- enforce one-position-per-asset
    direction TEXT NOT NULL CHECK (direction IN ('LONG','SHORT')),
    entry_price DOUBLE PRECISION NOT NULL,
    stop_loss DOUBLE PRECISION NOT NULL,
    take_profit DOUBLE PRECISION NOT NULL,
    position_size_usdt DOUBLE PRECISION NOT NULL,
    entry_score DOUBLE PRECISION NOT NULL,
    entry_confidence DOUBLE PRECISION NOT NULL,
    entry_atr DOUBLE PRECISION NOT NULL,
    bars_held INTEGER NOT NULL DEFAULT 0,
    opened_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_check_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    signal_id TEXT NOT NULL UNIQUE
);

-- Per-asset cooldown tracker (in-memory cache + DB persistence for crash safety)
CREATE TABLE shadow_cooldowns (
    symbol TEXT PRIMARY KEY,
    cooldown_until TIMESTAMPTZ NOT NULL
);
```

## 5. Signal trigger logic

### 5.1 Entry conditions (per closed candle, per asset)

**Open LONG when ALL true:**
- `final.score > +0.30`
- `final.confidence > 0.50`
- No open position on this asset
- Not in cooldown for this asset (`shadow_cooldowns` shows past `cooldown_until`)
- Data quality validator passes for this candle

**Open SHORT when ALL true:**
- `final.score < -0.50` (asymmetric — stricter than long, per spec)
- `final.confidence > 0.50`
- No open position on this asset
- Not in cooldown
- Data quality validator passes

### 5.2 SL/TP computation

Same ATR-based formula as `core.predictor.build_prediction(...)`:

- **LONG:** `SL = entry - 1.5 × ATR(14)`, `TP = entry + 3.0 × ATR(14)`
- **SHORT:** `SL = entry + 1.5 × ATR(14)`, `TP = entry - 3.0 × ATR(14)`

### 5.3 Exit conditions (checked per closed candle)

For each open position, check current candle's `[low, high]` range:

- **LONG:** if `low ≤ SL` → close at SL (assume worst case fill); else if `high ≥ TP` → close at TP. If both touched (rare), close at SL (pessimistic, matches paper engine).
- **SHORT:** mirror.
- **Timeout:** if `bars_held ≥ 24` → close at this candle's `close` price.

After close:
- Insert `shadow_trades` row (hash-chained)
- Delete from `shadow_open_positions`
- Set `shadow_cooldowns.cooldown_until = now() + 30 min`
- Publish via WebSocket `shadow_updates` channel

## 6. Multi-stream Binance integration

### 6.1 Combined stream endpoint

Binance provides `wss://fstream.binance.com/stream?streams=` with multiple stream names joined by `/`:

```
wss://fstream.binance.com/stream?streams=btcusdt@kline_1h/ethusdt@kline_1h/...
```

One TCP connection serves all 30 assets. Lower memory + connection count vs 30 separate sockets.

### 6.2 Stream message format

Each message:
```json
{
  "stream": "btcusdt@kline_1h",
  "data": {
    "e": "kline",
    "E": 1714521600000,
    "s": "BTCUSDT",
    "k": {
      "t": 1714521600000, "T": 1714525199999,
      "s": "BTCUSDT", "i": "1h",
      "o": "65000", "c": "65300", "h": "65500", "l": "64800",
      "v": "1234.56", "x": true
    }
  }
}
```

Worker dispatches by `s` (symbol) to the per-asset evaluation pipeline.

### 6.3 Reconnect + gap-fill

Reuses existing `BinanceKlineStream` reconnect logic (per §5.8 SP-0 spec). On reconnect:

- For each asset, REST-fetch any closed candles since `last_seen_ts` (gap-fill)
- Replay through scoring pipeline (will not generate retroactive trades — only the latest closed bar can produce a new entry signal; earlier closed bars are scored for indicator state but don't trigger new positions)

### 6.4 Memory budget per asset

- In-memory `bars` DataFrame: 500 bars × 5 cols × 8 bytes ≈ 20 KB per asset
- 30 assets × 20 KB = 600 KB total bar storage
- Plus indicator computation overhead: another ~5 MB working memory total
- **Well within the 4 GB backend allocation**

## 10. Computed metrics — formulas

### 10.1 Win rate

```
win_rate = count(trades where pnl_pct > 0) / count(trades)
```

Computed over the rolling 30-day window for the gate; lifetime for total stats.

### 10.2 Sharpe ratio (annualized)

```
returns = [pnl_pct / 100 for each closed trade in window]
mean_return = mean(returns)
std_return  = stddev(returns)
trades_per_year = trades_in_window × (365 / window_days)
sharpe = (mean_return / std_return) × sqrt(trades_per_year)
```

If `std_return == 0` (only 1 trade, or all identical), Sharpe is undefined → display as "—".

### 10.3 Max drawdown

```
equity = cumsum(pnl_usdt for each closed trade in window)
running_max = expanding max of equity
drawdown = (equity - running_max) / running_max
max_dd = abs(min(drawdown))
```

Reported as positive %.

### 10.4 Profit factor

```
gross_profit = sum(pnl_usdt for winning trades)
gross_loss   = abs(sum(pnl_usdt for losing trades))
profit_factor = gross_profit / gross_loss
```

If `gross_loss == 0` (no losses yet), display as "∞".

### 10.5 Average RR

```
avg_rr = mean(abs(tp - entry) / abs(entry - sl))  # at trade-creation time
```

## 11. Cross-cutting policy compliance (meta-plan §5)

- **§5.1 Look-ahead bias:** signal evaluation uses ONLY data ≤ current closed bar (no peeking). Same as SP-0.
- **§5.2 Survivorship bias:** asset universe uses point-in-time top-30 (snapshot at decision time, not retroactive). Falling-out assets keep their existing trades; no retroactive deletion.
- **§5.3 Feature store:** scoring uses same `core.scoring.aggregator` as Tab 1 — no train/serve skew.
- **§5.4 Inputs hash:** every `shadow_trades` row stores `inputs_hash` for reproducibility per §5.4.
- **§5.7 Cold-start:** new assets in the top-30 use the global brain (no per-asset adapter yet — that's SP-4). Tagged `cold_start: true` until ≥ 100 trades on that asset.
- **§5.8 WebSocket reliability:** combined stream uses same reconnect+gap-fill pattern as SP-0 single-asset stream.
- **§5.9 Data quality gate:** existing validator runs on every incoming candle; failures skip signal generation for that asset/bar.
- **§5.11 TimescaleDB chunking:** `shadow_trades` chunked by `opened_at` (1-day chunks); compressed > 90 days; 2-year retention.
- **§5.12 Memory budget:** + ~150 MB for 30 streams + ~5 MB for indicator workspaces. Within backend allocation.
- **§5.13 Backups:** new tables included in existing pg_dump cron.
- **§5.14 Audit hash chain:** `shadow_trades` is hash-chained per existing pattern.
- **§5.15 Rate limits:** combined stream is 1 connection; well within Binance's 24-connection limit.

## 12. Failure modes + handling

| Failure | Detection | Action |
|---|---|---|
| Combined Binance stream drops | WS heartbeat missed | Reconnect with backoff; on resume, REST gap-fill all 30 assets |
| Universe refresh REST fails | exception in cron task | Use last-cached universe; log dq_alert; retry next refresh |
| Single asset has bad/missing data | data quality validator rejects | Skip signal generation for that bar; log dq_alert |
| Open position on asset that fell out of top-30 | universe refresh detects | Allow position to close naturally; don't re-enter |
| Shadow worker crashes mid-loop | uvicorn restarts container | On startup, load `shadow_open_positions` from DB; resume monitoring |
| Postgres unreachable mid-trade-write | exception | Retain trade in memory; retry insert with backoff (up to 5 min); if persistent, freeze worker + alert |
| ATR computation returns NaN (insufficient bars) | check before SL/TP | Skip the signal; log warning |
| Multiple closed candles arrive simultaneously (e.g., on reconnect) | normal | Process in timestamp order; cooldowns prevent double-entries |

## 16. SP-0.5 → SP-0.7 → SP-1 sequencing

This sub-project ships SHIPS first. Then:

1. **SP-0.7 multi-user wraps SP-0.5** by adding `user_id` to `shadow_trades`, `shadow_open_positions`, `shadow_cooldowns`. Migration script: `UPDATE … SET user_id = 1`. Each user's shadow worker runs on the SAME 30 assets (universe is shared) but maintains their own positions and stats.

2. **SP-1 ML data pipeline** uses the accumulated `shadow_trades` history as part of its training data (90+ days × 30 assets × ~5 trades/day = ~13,500 labeled trades for the brain to learn from). This is a HUGE benefit — SP-0.5 doubles as labeling infrastructure.

3. **SP-4 RL brain** swaps in as L10 of the scoring engine; shadow worker automatically picks it up (no SP-0.5 code changes needed).

4. **SP-7 champion-challenger** uses `shadow_trades` from both champion + challenger models running in parallel for the 14-day shadow window.

5. **SP-8 autonomous trading** is essentially "swap shadow_engine.execute() with live_engine.execute()" — same scoring, same SL/TP logic, same exit monitoring.

So **SP-0.5 is genuinely the foundation** for everything downstream. Worth doing right.
