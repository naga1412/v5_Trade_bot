# PR10.6 — hotfix: WS routing match-all + per-row stats timestamps

**Status:** spec drafted 2026-05-20 (same morning operator caught PR10.5 gaps via dashboard inspection). Hotfix shape — small surface, 2 commits, recording-behavior fix (no flag-gating).

**Branch:** `feat/pr10.6-hotfix-open-positions-data` (off `origin/dev`).

**Trigger:** Operator's dashboard verification showed PR10.5 had two unmet user-visible promises despite shipped status:
1. Open Positions Now / P&L columns still empty in prod.
2. Per-asset stats card only had a card-level "as of" footer, not per-row timestamps.

---

## 1. Diagnosis (code-level, no probe needed)

### T-UI.1 root cause — PRE-EXISTING WS routing bug since SP-0.5

`backend/app/ws/manager.py:18-19`:

```python
def _key_matches(sub_params: dict[str, Any], publish_key: dict[str, Any]) -> bool:
    return all(sub_params.get(k) == v for k, v in publish_key.items())
```

The function iterates `publish_key.items()`, so when the publisher emits with `key={"symbol": "BTCUSDT"}` and the subscriber subscribed with `params={}` (whole-channel, no symbol filter), the comparison evaluates `sub_params.get("symbol") == "BTCUSDT"` → `None == "BTCUSDT"` → `False`. Every symbol-scoped event is silently filtered out.

`frontend/src/hooks/useShadowUpdates.ts:113` subscribes with `sock.subscribe(CHANNEL, {})` (empty params). So PR10.5's new `publish_pnl_tick` calls fire — but the frontend never receives them. The bug has been silently filtering `shadow_position_opened`, `shadow_position_closed`, and now `shadow_pnl_tick` since SP-0.5 launched.

Hidden by: `backend/tests/integration/test_ws_shadow_updates.py:184` only tests `params={"symbol": "BTCUSDT"}` — never the empty-params case the frontend actually uses.

### T-UI.3 root cause — frontend rendering gap

The backend `/api/v1/bot-status/per-asset` route at `backend/app/api/routes/bot_status.py:599-621` already computes `last_trade_closed_at` per symbol (one value per row in the response). PR10.5 wired this through the schema correctly.

The frontend `frontend/src/tabs/BotStatus/PerAssetTable.tsx:138-148` only renders `sorted[0]?.last_trade_closed_at` in a card-level footer. Each row's per-symbol value is in the data but never rendered. Pure frontend gap.

## 2. Scope

### Commit 1 (backend WS routing fix)

- Modify `_key_matches` in `backend/app/ws/manager.py`: treat empty `sub_params` as match-all for the channel. New body:
  ```python
  def _key_matches(sub_params: dict[str, Any], publish_key: dict[str, Any]) -> bool:
      # PR10.6 hotfix: empty sub_params = "subscribe to whole channel" semantics.
      # Pre-fix, the all(sub_params.get(k) == v ...) returned False whenever the
      # publisher emitted with a non-empty key (e.g. {"symbol": "BTC..."}) but the
      # subscriber filtered nothing — silently dropping every symbol-scoped event.
      # Frontend uses params={} so this filtered out shadow_position_opened /
      # shadow_position_closed / shadow_pnl_tick (the PR10.5 wiring) since SP-0.5.
      if not sub_params:
          return True
      return all(sub_params.get(k) == v for k, v in publish_key.items())
  ```
- Add integration test in `backend/tests/integration/test_ws_shadow_updates.py`: subscribe with `params={}`, publish `shadow_pnl_tick` for a specific symbol, assert the subscriber received it.

### Commit 2 (frontend per-row timestamps)

- Add a "Last trade" column to `PerAssetTable.tsx` rendering `s.last_trade_closed_at` per row as relative time ("3m ago" / "2h ago" / "—").
- Add a small `formatRelativeTime(iso: string | null): string` helper. Place it inline in the component OR in a shared util (`frontend/src/lib/time.ts` if it doesn't exist — keep simple).
- Drop the card-level `last trade {timestamp}` from the footer (kept `computed at` since that's per-card, not per-row).
- Update `frontend/tests/unit/PerAssetTable.test.tsx`: assert each row shows its own relative-time stamp; null → "—".
